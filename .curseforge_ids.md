## Upload Command
```powershell
$meta = @{
  changelog         = "## 1.7.0 ..."
  changelogType     = "markdown"
  displayName       = "Upshift 1.7.0 (NeoForge)"
  releaseType       = "beta"
  gameVersionNames  = @("Client","NeoForge","26.2")   # or ("Client","Fabric","26.2")
}
$metaFile = "$env:TEMP\cf-meta.json"
[System.IO.File]::WriteAllText($metaFile, ($meta | ConvertTo-Json -Depth 5), [System.Text.UTF8Encoding]::new($false))

curl.exe -sS -X POST "https://minecraft.curseforge.com/api/projects/<projectID>/upload-file" `
    -H "X-Api-Token: $env:CF_API_TOKEN" `
    -F "metadata=<$metaFile;type=application/json" `
    -F "file=@<jarPath>;type=application/java-archive" `
    -w "`nHTTP_STATUS=%{http_code}"
```

The `metadata=<$metaFile` (stdin) form is required. curl `-F "metadata=@file"` returns 400,
and a retried request fails because the body has already been consumed.

## Local Paths
- Base Fabric: `fabric/build/libs/upshift-<version>.jar` (ignore `-sources.jar`)
- Base NeoForge: `neoforge/build/libs/upshift-<version>.jar`
- VR Fabric: `fabric/upshift-vr-edition/build/libs/upshift_vr_edition-<version>.jar`
- VR NeoForge: `neoforge/upshift-vr-edition/build/libs/upshift_vr_edition-<version>.jar`

## Key Reminders
- Never republish the old VR file 9542294 unless explicitly asked; it is a dead Fabric-era attempt.
- The token lives in `$env:CF_API_TOKEN`.
- Files can only be uploaded through this endpoint. Listing and deleting files over the API
  return 403 with this token, so cleanup happens at authors.curseforge.com.
